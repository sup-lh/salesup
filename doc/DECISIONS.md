# 决策记录

## D-001：后端技术栈

状态：已决定

保留 React + NestJS + Drizzle。脱离妙搭不要求切换 Spring，Spring 仅在团队 Java 标准或既有 Spring 基础设施成为明确约束时重新评估。

## D-002：数据库访问边界

状态：已决定

React 不直接连接 PostgreSQL。浏览器只调用 NestJS API，数据库凭据只存在服务端。

## D-003：独立版权限

状态：已决定

保留管理员 RBAC。当前系统已经有管理端路由和 action/subject 权限表达，先迁移权限能力，后续再根据实际使用情况下线角色管理页面。

## D-004：业务数据

状态：已决定

独立版从空数据库开始，不迁移妙搭历史业务数据。后续只通过正式初始化/种子数据创建新系统所需的角色、权限和基础配置。

## D-005：文件存储

状态：已决定

开发和生产环境统一以 MinIO 作为第一版对象存储。后续如有需要，再替换为 S3/OSS 兼容服务。当前飞书链接保留为普通外链，不再作为平台能力依赖。

## D-006：通知

状态：已决定

转正面试申请使用站内通知，不再调用飞书消息 capability；通知写入与业务事务保持清晰边界，不让通知失败阻断核心业务事务。

## D-007：迁移方式

状态：已决定

采用兼容适配器和逐模块替换，不一次性删除妙搭依赖，不直接修改原始 table.sql。

## 待用户确认

无。

## D-008：账号体系收尾边界

状态：已决定

本轮保留本地用户名密码、Session 和 RBAC，不接入企业 SSO/OIDC。

## D-009：收尾交付边界

状态：已决定

交付标准为仓库完成代码、自动化测试、Docker 验收、生产配置和备份恢复文档；不操作未提供的外部生产服务器。
